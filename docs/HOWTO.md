## 1. Как работает бот

**Для новичка:**

1. Человек вступает в группу по ссылке, без заявки и ожидания. Он сразу видит переписку,
   но писать не может.
2. Служебное сообщение «… вступил(а) в группу» бот удаляет и публикует приветствие
   с кнопкой «Ответить на вопрос».
3. Кнопка открывает личку с ботом. Бот задаёт случайный вопрос из вашего списка. Один и тот же
   человек всегда получает один и тот же вопрос, даже если выйдет и вступит снова.
4. Верный ответ: бот снимает ограничение, удаляет приветствие и всю переписку о проверке,
   оставляет в личке одно сообщение «Теперь вы можете писать в группе».
5. Неверный ответ: бот сообщает, сколько осталось попыток. Каждый текстовый ответ тратит попытку,
   даже если он не в том формате (например, слово вместо цифр). Стикеры, фото и прочее
   попыткой не считаются, бот просто просит ответить текстом.
6. Исчерпаны попытки (по умолчанию 3): вечный бан. Снять его может администратор.
7. Не ответил за 48 часов: бот удаляет человека из группы (без бана). Он может вступить снова,
   использованные попытки сохраняются.

**Кого бот не трогает:**

- участников, которые были в группе до установки бота;
- людей, которых добавил в группу администратор;
- тех, кого администратор однажды одобрил или разбанил.

**Для администраторов:** по каждому новичку бот присылает каждому администратору одно
сообщение в личку и обновляет его по ходу дела:

| Событие | Уведомление | Кнопки |
|---|---|---|
| Вступил, ждёт ответа | 🆕 … Попыток: 3 | ✅ Одобрить, ⛔ Забанить |
| Ответил верно | ✅ Проверка пройдена | — |
| Исчерпал попытки | ⛔ Бан после 3 неверных ответов | ↩️ Разбанить |
| Вышел до проверки | 🚪 Вышел из группы до проверки | — |
| Удалён по таймауту | ⌛ Удалён из группы | — |

Если администратор сам банит, разбанивает или снимает ограничение в обычном интерфейсе
Telegram, бот это замечает и обновляет уведомление.

**Защита от ботов.** Вопрос нельзя найти поиском по группе: он задаётся в личке. Часть русских
букв в тексте вопроса бот заменяет похожими латинскими (а → a, о → o, р → p…), так что текст
выглядит обычно, но не совпадает при поиске и сбивает простые программы. Ответ проверяется
мягко: регистр, «ё/е», «й/и», пробелы, знаки и случайно набранные латинские буквы не важны.

## 2. Что понадобится

- **Telegram-группа**, где вы владелец или администратор с правом назначать администраторов.
- **Аккаунт Cloudflare** — бесплатного тарифа хватает с огромным запасом: 100 000 запросов
  в день, а группе на тысячу человек нужно несколько сотен.
- **Компьютер с Linux или macOS** (на Windows — через WSL) с программами:
  - `bash`, `curl` — обычно уже есть;
  - `jq` — `brew install jq` на macOS, `sudo apt install jq` в Debian/Ubuntu;
  - **Node.js 20 или новее** — с [nodejs.org](https://nodejs.org) или `brew install node`.
    Инструмент Cloudflare `wrangler` скрипты скачают сами.

  На NixOS или с Nix достаточно `nix develop` в папке проекта.
- **Второй аккаунт Telegram** для проверки — желательно, но не обязательно.

Компьютер нужен только для установки и изменений. Сам бот работает в Cloudflare,
компьютер можно выключить.

## 3. Бот в Telegram

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`.
2. Придумайте имя (видно в чате, например «Привратник Соседи») и username,
   оканчивающийся на `bot`.
3. BotFather пришлёт **токен** вида `123456789:AAH…`. Это пароль от бота: никому
   не пересылайте, не публикуйте и не вставляйте в файлы. Скрипт установки спросит его
   один раз и сохранит только в Cloudflare.
4. Необязательно, но полезно:
   - `/setprivacy` → ваш бот → **Disable**. Бот-администратор и так видит все сообщения.
   - `/setdescription` — текст, который человек видит, открыв бота, например:
     «Проверяю новых участников группы „Соседи“. Нажмите Start и ответьте на вопрос».
   - `/setuserpic` — аватар.

Если токен всё же попал в чужие руки: в BotFather `/revoke` → ваш бот, затем
`scripts/deploy.sh --token` с новым токеном.

## 4. Группа

1. **Супергруппа.** Бот работает только в супергруппах. Публичные группы (с @username)
   ими являются всегда. Если группа закрытая и скрипт установки скажет, что это не
   супергруппа: в настройках группы включите «История чата для новых участников» → «Видна».
   Telegram преобразует группу в супергруппу.
2. **Заявки выключены.** В настройках группы → «Тип группы» отключите «Одобрение новых
   участников» (заявки на вступление). Бот рассчитан на свободное вступление.
3. **Добавьте бота администратором**: «Администраторы» → «Добавить администратора» →
   найдите бота по username. Права:
   - ✅ **Удаление сообщений**
   - ✅ **Блокировка пользователей**
   - ✅ **Управление темами** — только если в группе есть темы и тема «Общее» закрыта
     для участников (см. ниже)
   - остальное можно выключить.
4. **Каждый администратор** группы должен один раз открыть бота и нажать **Start** —
   иначе Telegram не разрешит боту присылать ему уведомления. Проверку бот у администраторов,
   конечно, не проводит.

**Группы с темами (форум).** Приветствие публикуется в теме «Общее». Если она открыта и видна —
ничего настраивать не нужно. Если вы хотите приветствие в другой теме (например «Знакомство»),
скопируйте ссылку на эту тему (долгое нажатие или правый клик по теме → «Копировать ссылку»):
число в конце ссылки — ID темы. Впишите его в `PROMPT_THREAD_ID` в `config.env`.

**Внимание:** если в вашей группе более 100 участников, Telegram позволяет скрыть их список. Включите эту опцию, чтобы спамеры не писали людям индивидуально с целью мошенничества.

## 5. Cloudflare

1. Зарегистрируйтесь на [dash.cloudflare.com](https://dash.cloudflare.com). Домен для этого не нужен.
2. **Поддомен workers.dev.** В меню слева откройте **Workers & Pages** (в новом меню — в группе
   **Compute**). Если Cloudflare предлагает выбрать поддомен `*.workers.dev`, выберите любой — бот будет жить по
   адресу `https://<WORKER_NAME>.<поддомен>.workers.dev`. Без этого первая установка
   остановится с ошибкой про subdomain.
3. **Account ID.** На той же странице справа есть **Account ID** — скопируйте.
4. **API-токен.** Справа вверху иконка профиля → **My Profile → API Tokens → Create Token →
   Create Custom Token** (внизу, «Get started»). Название — например `tg-gatekeeper`.
   Права (Permissions):

   | Тип | Ресурс | Доступ | Зачем |
   |---|---|---|---|
   | Account | Workers Scripts | Edit | загрузить бота, его секреты и расписание |
   | Account | D1 | Edit | создать базу данных и таблицы |
   | Account | Workers Tail | Read | журнал бота (`scripts/bot.sh logs`) |
   | Account | Account Settings | Read | wrangler находит ваш аккаунт |

   Account Resources: **Include → ваш аккаунт**. Остальное оставьте как есть.
   Права «User → Memberships» и «User → User Details» **не нужны** — Account ID вы укажете сами.
   Нажмите **Continue → Create Token** и скопируйте токен (он показывается один раз).

## 6. Настройки: config.env

Скачайте проект (`git clone …` или «Download ZIP» на GitHub) и в его папке:

```sh
cp config.example.env config.env
```

Откройте `config.env` в редакторе:

| Параметр | Что это | По умолчанию |
|---|---|---|
| `CLOUDFLARE_ACCOUNT_ID` | Account ID из шага 5 | — |
| `CLOUDFLARE_API_TOKEN` | API-токен из шага 5 | — |
| `WORKER_NAME` | имя бота в Cloudflare: латиница, цифры, дефис. Так же будет называться база | `tg-gatekeeper` |
| `GROUP` | `@username` публичной группы или числовой ID закрытой (см. ниже) | — |
| `MAX_ATTEMPTS` | сколько неверных ответов до бана | `3` |
| `REMOVE_AFTER_HOURS` | через сколько часов удалять не ответивших | `48` |
| `OBFUSCATE_RATE` | доля букв вопроса, заменяемых латинскими двойниками; `0` — выключить | `0.25` |
| `PROMPT_THREAD_ID` | тема для приветствия в группе с темами; пусто — «Общее» | пусто |

`config.env` содержит API-токен Cloudflare — он перечислен в `.gitignore` и не попадёт в git.
Не пересылайте его.

**ID закрытой группы.** Добавьте бота в группу (шаг 4), напишите в группе любое сообщение и
запустите:

```sh
scripts/find-chat.sh
```

Скрипт спросит токен бота и покажет группы, которые бот видел, с их ID (`-100…`). Это работает
только до первой установки; потом используйте `scripts/bot.sh chat -100…`.

## 7. Вопросы: questions.json

```sh
cp questions.example.json questions.json
```

`questions.json` содержит ответы — он тоже в `.gitignore`. Пример:

```json
{
  "welcome": "Добро пожаловать, {name}! Чтобы писать в группе, ответьте на один вопрос о нашем районе.",
  "intro": "Пожалуйста, подтвердите, что вы живёте в нашем районе, ответив на вопрос.",
  "questions": [
    { "id": "bus", "kind": "digits", "length": 3,
      "text": "Какой номер у автобуса, который идёт от ближайшей к дому остановки до метро? Впишите три цифры.",
      "answers": ["123"] },
    { "id": "zip", "kind": "digits", "length": 6,
      "text": "Какой почтовый индекс у нашего дома? Впишите 6 цифр.",
      "answers": ["123456"] },
    { "id": "school", "kind": "free",
      "text": "Какой номер у школы во дворе нашего дома? Можно цифрами или словом.",
      "answers": ["5", "пятая"] }
  ]
}
```

| Поле | Смысл |
|---|---|
| `welcome` | приветствие в группе; `{name}` заменяется ссылкой на новичка. Необязательно |
| `intro` | первая строка в личке перед вопросом |
| `id` | короткое имя вопроса латиницей, уникальное. Видно в `scripts/bot.sh list` |
| `kind` | `digits` — ответ из цифр фиксированной длины; `free` — число или слово |
| `length` | для `digits`: сколько цифр. Если человек ввёл не столько цифр, бот подскажет формат (попытка всё равно тратится) |
| `text` | текст вопроса |
| `answers` | все принимаемые ответы |

**Как сравниваются ответы.** И ответ человека, и ваши варианты приводятся к одному виду:
нижний регистр, «ё» → «е», «й» → «и», латинские двойники → русские буквы, удаляется всё,
кроме букв и цифр. Поэтому «Пятая», «ПЯТАЯ» и «пятая.» совпадают.
Для `free`: если в ответе есть цифры, сравниваются только цифры — «5-я», «№5», «5я»
совпадают с «5». Для `digits` ответ «123 456» совпадёт с «123456».

**Хороший вопрос:**

- ответ знает любой «свой», но его нельзя угадать или быстро нагуглить по названию группы;
- однозначный ответ: номер, индекс, название — не мнение;
- если ответ можно написать по-разному, перечислите варианты в `answers`;
- 3–5 вопросов достаточно. Разные новички получают разные вопросы, поэтому один
  «слитый» ответ не открывает дверь всем.

Скрипт установки проверяет файл и откажется загружать его с ошибками или без изменений
по сравнению с примером.

## 8. Установка

В папке проекта:

```sh
scripts/deploy.sh
```

Скрипт:

1. проверит `config.env` и `questions.json`;
2. спросит токен бота (ввод не отображается) и через Telegram проверит, что группа —
   супергруппа без заявок и что у бота есть нужные права;
3. создаст в Cloudflare базу данных и таблицы;
4. создаст случайный секрет, которым Telegram подписывает запросы к боту;
5. загрузит бота с токеном, секретом и вопросами как зашифрованными секретами Cloudflare;
6. подключит бота к Telegram и покажет итог:

```
{
  "bot": "my_gatekeeper_bot",
  "status_in_group": "administrator",
  "can_delete_messages": true,
  "can_restrict_members": true,
  "questions": ["bus", "zip", "school"],
  "webhook": { "url": "https://tg-gatekeeper.example.workers.dev/webhook", "pending": 0 }
}
› Готово. Бот работает в группе.
```

С этого момента бот проверяет всех, кто вступает. Скрипт сохраняет найденное (ID группы, адрес
бота, секрет) в `.state.env` — не удаляйте и не публикуйте этот файл.

Проверить настройки без загрузки: `scripts/deploy.sh --dry-run`.

**Совет:** сначала установите бота в пустую тестовую группу (`GROUP` = тестовая), проверьте по
шагу 9, затем впишите настоящую группу и запустите `scripts/deploy.sh --token`.

## 9. Проверка

Удобнее всего со вторым аккаунтом Telegram, который не администратор группы.

| # | Действие | Ожидание |
|---|---|---|
| 1 | Вступить в группу по ссылке | Писать нельзя; сообщения «вступил(а)» нет; есть приветствие с кнопкой; администраторам пришло 🆕 |
| 2 | Нажать «Ответить на вопрос», затем Start | Вступление и вопрос; некоторые буквы латинские |
| 3 | Отправить стикер | «Пожалуйста, ответьте текстовым сообщением», попытка не потрачена |
| 4 | Отправить неверный ответ | «Неверно. Осталось попыток: 2» |
| 5 | Отправить верный ответ | «Спасибо!…»; писать можно; приветствие и переписка удалены; у администраторов ✅ |
| 6 | `scripts/bot.sh reset <ID>`, выйти, вступить снова, трижды ответить неверно | Бан; у администраторов ⛔ с кнопкой «Разбанить» |
| 7 | Нажать «Разбанить» | Человек может вступить без проверки; в личку пришла ссылка |
| 8 | `scripts/bot.sh reset <ID>`, вступить, выйти до ответа | 🚪; при новом вступлении — тот же вопрос и оставшиеся попытки |
| 9 | Администратор добавляет человека через «Добавить участника» | Проверки нет |

ID второго аккаунта показывает `scripts/bot.sh list`.

После тестов удалите записи тестового аккаунта (`scripts/bot.sh reset <ID>`), чтобы он не
считался проверенным, если это важно.

## 10. Повседневная работа

Обычно ничего делать не нужно. Администраторы получают уведомления и, если нужно,
нажимают кнопки:

- **✅ Одобрить** — пустить без ответа (например, знакомого, который не может ответить).
- **⛔ Забанить** — сразу забанить, удалив его сообщения.
- **↩️ Разбанить** — снять бан. Разбаненный дальше считается проверенным и может вступить
  без вопроса.

Кнопки работают только у администраторов группы. Того же результата можно добиться обычными
средствами Telegram: бан, разбан, снятие ограничений в профиле участника — бот это учтёт.

**Таймауты.** Раз в час бот убирает старые приветствия и удаляет тех, кто не ответил за
`REMOVE_AFTER_HOURS`. Поэтому удаление происходит в течение часа после срока. Приветствие
удаляется не позже 46–47 часов: Telegram не даёт ботам удалять сообщения старше 48 часов.

## 11. Команды обслуживания

```sh
scripts/bot.sh КОМАНДА
```

| Команда | Что делает |
|---|---|
| `status` | права бота, загруженные вопросы, состояние связи с Telegram |
| `chat [@группа]` | ID группы, есть ли темы, права бота |
| `list` | все записи: кто ждёт, кто прошёл, кто забанен, сколько ошибок |
| `user ID` | что знают о человеке Telegram и база бота |
| `release ID` | снять оставшееся ограничение с человека, который уже не в группе |
| `reset ID` | забыть человека: при следующем вступлении — проверка с нуля |
| `sweep` | выполнить почасовую уборку прямо сейчас |
| `questions` | проверить и загрузить `questions.json` без полной переустановки |
| `logs` | журнал бота в реальном времени, Ctrl+C — выход |

Журнал также есть в панели Cloudflare: Workers & Pages → ваш бот → **Logs**.

## 12. Изменения и обновления

| Что изменить | Как |
|---|---|
| Вопросы | правьте `questions.json`, затем `scripts/bot.sh questions`. Новые вопросы получат новые вступающие; у тех, кто уже ждёт и чей вопрос удалён, будет случайный новый |
| Параметры из `config.env` | правьте и запустите `scripts/deploy.sh` |
| Другая группа | `GROUP` в `config.env`, затем `scripts/deploy.sh --token` |
| Токен бота | `/revoke` в BotFather, затем `scripts/deploy.sh --token` |
| Новая версия проекта | `git pull`, затем `scripts/deploy.sh` |

`scripts/deploy.sh` можно запускать сколько угодно раз: он не трогает базу и ничего не
создаёт заново.

## 13. Ограничения

- **Одна установка — одна группа и один бот.** Для второй группы создайте второго бота в
  BotFather и скопируйте проект в другую папку с другим `WORKER_NAME`.
- Бот не проверяет тех, кто уже был в группе до его установки.
- Бот может написать человеку в личку, только если тот сам открыл бота. Поэтому сообщения
  «вас удалили» и «бан снят» получат лишь те, кто хотя бы раз нажимал Start.
- Telegram не даёт ботам удалять сообщения старше 48 часов.
- После одобрения Telegram показывает человека как «ограниченного», хотя его права
  совпадают с правами по умолчанию для всех участников. Это особенность Telegram,
  на работу не влияет. Если позже вы расширите права группы, бот это учтёт только у новых
  одобренных; уже одобренным можно снять ограничения вручную.
- Если у бота отобрать права администратора, он перестанет проверять новичков; те, кто уже
  ждёт ответа, останутся с ограничением.
- **Какие данные хранятся** (база D1 в вашем аккаунте Cloudflare): Telegram ID и имя
  новичка, статус, номер вопроса, число ошибок, время вступления и ID служебных сообщений.
  Тексты ответов не сохраняются. Записи о прошедших проверку остаются, чтобы их не проверять
  повторно; удалить можно через `scripts/bot.sh reset ID`.

## 14. Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| Новичка не ограничивают, приветствия нет | `scripts/bot.sh status`: бот должен быть `administrator` с обоими правами; в `webhook` не должно быть `last_error`. Посмотрите `scripts/bot.sh logs` во время вступления |
| Приветствия нет в группе с темами | Тема «Общее» закрыта: дайте боту право «Управление темами» или укажите другую тему в `PROMPT_THREAD_ID` |
| Администратору не приходят уведомления | Он не нажал Start в личке с ботом |
| Человек вышел и пишет, что «группа недоступна» при вступлении | Осталось ограничение: `scripts/bot.sh release ID` |
| Не удаляются не ответившие | Расписание после первой установки включается до 15 минут; дальше — раз в час. `scripts/bot.sh sweep` запускает уборку сразу |
| `deploy.sh`: ошибка про workers.dev subdomain | Выберите поддомен в панели Cloudflare (шаг 5.2) |
| `deploy.sh`: Authentication error | Проверьте Account ID и права API-токена (шаг 5.4) |
| `find-chat.sh`: «вебхук уже подключён» | Бот уже установлен — используйте `scripts/bot.sh chat -100…` |
| `scripts/bot.sh …`: Forbidden | `.state.env` не совпадает с установленным ботом — запустите `scripts/deploy.sh` |

## 15. Удаление

1. Удалите бота из администраторов и из группы.
2. В папке проекта:

   ```sh
   npx wrangler delete                  # бот в Cloudflare
   npx wrangler d1 delete <WORKER_NAME> # база данных
   ```

   (переменные `CLOUDFLARE_*` из `config.env` должны быть в окружении:
   `set -a; source config.env; set +a`).
3. В BotFather: `/deletebot` — или `/revoke`, если бот ещё пригодится.
4. Удалите API-токен в Cloudflare: My Profile → API Tokens.

## 16. Как устроен проект

```
config.example.env       шаблон настроек → config.env (не в git)
questions.example.json   шаблон вопросов → questions.json (не в git)
schema.sql               таблицы базы данных
src/index.ts             бот: один файл TypeScript без зависимостей
scripts/deploy.sh        установка и обновление
scripts/bot.sh           команды обслуживания
scripts/find-chat.sh     ID закрытой группы до установки
scripts/lib.sh           общие функции скриптов
flake.nix                окружение для Nix (nix develop)
```

Создаются при установке и не попадают в git: `wrangler.jsonc` (генерируется из
`config.env` при каждом запуске `deploy.sh` — не правьте его руками), `.state.env`
(ID группы, адрес бота, секрет вебхука).

**Схема работы.** Telegram отправляет события группы (вступления, сообщения, нажатия кнопок)
на адрес бота в Cloudflare Workers, подписывая каждый запрос секретом. Бот отвечает через
Telegram Bot API и хранит состояние новичков в базе D1. Раз в час Cloudflare запускает
уборку по расписанию.

**Секреты Cloudflare** (зашифрованы, в панели не видны): `BOT_TOKEN`, `WEBHOOK_SECRET`,
`QUESTIONS` — содержимое `questions.json`. **Переменные** (видны в панели): `CHAT_ID`,
`BOT_USERNAME`, `MAX_ATTEMPTS`, `OBFUSCATE_RATE`, `PROMPT_THREAD_ID`, `PROMPT_TTL_SEC`,
`REMOVE_AFTER_SEC`.

**Служебные адреса бота** (только POST с секретом, иначе 403): `/webhook` — события Telegram;
`/setup` — подключить вебхук и показать состояние; `/chat`, `/debug`, `/sweep` — для
`scripts/bot.sh`.

**Статусы в базе:** `pending` — в группе, ждёт ответа; `away` — не прошёл проверку и не в
группе (вышел или удалён по таймауту), попытки сохраняются; `verified` — прошёл или одобрен;
`banned` — забанен.
